# KF Production — Supabase admin migration

## Что подготовлено
- `supabase/functions/kf-admin/index.ts`: защищённый Edge Function API. Каждый запрос требует действующую Supabase-сессию и проверяет `public.is_kf_admin()`.
- `supabase/kf-admin-schema.sql`: таблица каталога, защищённые SQL-функции управления ролями и Storage bucket `kf-media`.
- `admin.js`: админка использует Supabase Auth и Edge Function вместо локальных Node API.
- Резервные копии прежних `admin.js` и `admin.html` находятся рядом с исходниками.

## Обязательные шаги в панели Supabase
1. Открой SQL Editor в проекте KF Production.
2. Открой локальный файл `supabase/kf-admin-schema.sql`, скопируй весь текст в SQL Editor и нажми Run. Таблицы/функции создаются идемпотентно.
3. Открой Edge Functions → функция `kf-admin`. Если функция уже создана, открой её редактор; иначе создай новую функцию с именем ровно `kf-admin`.
4. Замени код функции содержимым `supabase/functions/kf-admin/index.ts` и Deploy.
5. Проверь, что у функции доступны стандартные переменные окружения `SUPABASE_URL` и `SUPABASE_ANON_KEY` (или `SUPABASE_PUBLISHABLE_KEY`). Service-role key не нужен и в браузер не помещается.
6. Админ-панель: `https://torn23-web.github.io/KF_PRODUCTION/admin.html`. Вход — email и пароль уже существующего аккаунта Supabase, которому выданы права администратора.
7. Для добавления ещё администратора сначала создай ему обычный пользовательский аккаунт в Authentication → Users, затем скопируй его UUID в поле User UID на странице админки.

## Важные ограничения миграции
- Старые записи из `data/catalog.json` не переносятся автоматически: их нужно добавить заново в Supabase, либо выполнить отдельный импорт после проверки формата.
- Изменения каталога сейчас сохраняются в `kf_catalog`. Чтобы они появились на главной странице сайта, её каталог также нужно переключить на чтение этой таблицы. Пока основной сайт продолжает использовать существующий каталог/данные, не считай миграцию каталога полностью завершённой.
- Файлы в `kf-media` имеют публичные URL для воспроизведения; загрузка/изменение/удаление ограничены администратором.
- Админка не создаёт новые Auth-пользовательские аккаунты и не меняет их пароли: это делается в Supabase Authentication. Она только выдаёт/отзывает роль после проверки UUID.
